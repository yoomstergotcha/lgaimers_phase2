# 모델 구조 가이드라인 v2

## 0. 전체 방향

최종 구조는 **CatBoost 기반 ML Branch**와 **Structured Transformer 기반 DL Branch**를 결합하는 2-모델 앙상블이다.

두 모델의 목적은 서로 다르다.

- **CatBoost**: 사람이 정리한 통계적 Pitcher Profile과 Temporal Feature를 이용해 강한 단독 성능 확보
- **Transformer**: 동일한 원천 정보를 `Context × Time` 구조의 state token으로 재구성해 관계를 학습
- **Final**: 두 모델의 확률을 단순 blend

핵심 철학:

\[
\boxed{
Same\ Information\ Universe
+
Different\ Representation
+
Different\ Inductive\ Bias
}
\]

---

# 1. 공통 데이터 철학

## 1.1 Pitcher ID는 직접 입력하지 않음

`pitcher_id`는 모델 입력 categorical feature로 사용하지 않는다.

대신 historical aggregation key로만 사용한다.

```text
pitcher_id
    ↓
과거 기록 집계
    ↓
Pitcher Historical Profile
    ↓
pitcher_id 제거
    ↓
모델 입력
```

즉 모델이 투수의 ID를 외우는 대신:

```text
Career Profile
Situation Profile
Temporal Profile
Current State
```

를 통해 투수를 표현한다.

\[
\boxed{
Pitcher\ ID
\rightarrow
Pitcher\ Fingerprint
}
\]

---

## 1.2 Test row 독립성 유지

2025 inference에서는 각 test row를 독립적으로 예측한다.

금지:

```text
test row 간 shift
rolling
cumulative statistics
frequency encoding
test 기반 target/statistical update
```

허용:

```text
현재 행의 공식 asof_*
2019~2024에서 미리 계산한 frozen lookup
학습 완료된 모델
```

# PART A. Machine Learning Branch — CatBoost

# 3. CatBoost의 역할

CatBoost는 현재까지 가장 안정적인 주력 모델이다.

목표:

> **강한 statistical feature engineering을 통해 가능한 한 높은 standalone 성능을 확보한다.**

CatBoost는 다음을 잘 처리한다.

```text
저차원 numerical summary
categorical context
threshold interaction
nonlinear split
missing value
```

반대로 시간 순서 자체를 자연스럽게 이해하는 모델은 아니므로, temporal relationship은 일부 명시적으로 제공한다.

---

# 4. 기존 Base 구조

기존 Base263 계열의 핵심 block은 유지한다.

## 4.1 Career / Historical Profile

예:

```text
success
middle
reverse
ball
strike

fastball usage
breaking usage
offspeed usage

sample n
```

---

## 4.2 Situation Profile

주요 historical context:

```text
Overall
Batter Hand
Count
Count × Hand
BaseOut
Count × BaseOut
```

각 Context에서 control / pitch-mix / sample-size 정보를 제공한다.

---

## 4.3 Context Effect / Safe Context / HLogit

단순 raw rate뿐 아니라:

```text
context historical rate
overall historical rate
context effect
safe context
hierarchical logit
```

등을 이용해 sparse context를 안정적으로 표현한다.

---

## 4.4 Current State

장기 이력과 별도로 현재 상태를 표현한다.

```text
current-season profile
recent-game profile
asof profile
current vs historical deviation
```

---

## 4.5 Latent Skill

기존 Latent Skill은 CatBoost Branch에서 유지한다.

역할:

```text
복수 historical profile
→ 압축된 future-skill summary
```

단, Latent Skill은 temporal trajectory를 직접 보존하지 않으므로 아래 Seasonal Temporal Profile을 별도로 추가한다.

# 5. 새 핵심 Block — Temporal Profile

현재 Base는 Situation 축에 비해 Time 축이 상대적으로 압축되어 있다.

이를 보완하기 위해:

```text
Prev1
Prev2
Prev3
```

season-level profile을 추가한다.

예를 들어 2024 validation에서는:

```text
Prev1 = 2023
Prev2 = 2022
Prev3 = 2021
```

---

# 6. Temporal Level

각 season별 주요 metric:

```text
success
middle
reverse
ball
strike

fastball
breaking
offspeed

sample n
```

초기 실험에서는 level 표현을 두 방식으로 분리해서 비교한다.

## 6.1 Absolute Level

\[
p_{p,t}
\]

예:

```text
prev1_success
prev2_success
prev3_success
```

---

## 6.2 Relative Level

\[
p^{rel}_{p,t}=p_{p,t}-\mu_t
\]

여기서 \(\mu_t\)는 해당 시즌의 league-level 평균이다.

예:

```text
prev1_success_rel
prev2_success_rel
prev3_success_rel
```

중요:

> **Absolute와 Relative Level은 같은 run에 동시에 넣지 않는다.**

별도 arm으로 비교해 표현 자체의 효과를 확인한다.

---

# 7. Temporal Trend

Trend는 상대값을 우선한다.

절대 변화:

\[
p_{t-1}-p_{t-2}
\]

에는 개인 변화뿐 아니라 league drift가 섞인다.

따라서:

\[
\Delta^{rel}_{1,2}
=
(p_{t-1}-\mu_{t-1})
-
(p_{t-2}-\mu_{t-2})
\]

\[
\Delta^{rel}_{2,3}
=
(p_{t-2}-\mu_{t-2})
-
(p_{t-3}-\mu_{t-3})
\]

를 사용한다.

예:

```text
prev1_rel - prev2_rel
prev2_rel - prev3_rel
```

목적:

> **리그 전체 변화가 아니라 해당 투수의 상대적 위치가 실제로 개선/악화되었는지 측정**

---

# 8. Temporal Reliability

2024 기준 seasonal availability는 대략:

```text
Prev1  ≈ 73.7%
Prev2  ≈ 61.1%
Prev3  ≈ 50.5%
```

따라서 rate만 제공하지 않는다.

반드시:

```text
prev1_n
prev2_n
prev3_n
```

을 같이 제공한다.

CatBoost에서는 NaN native handling을 유지한다.

---

# 9. F-specific Temporal Profile

초기 V1에서는 다음과 같은 F-only seasonal lag는 만들지 않는다.

```text
F_prev1_success
F_prev2_success
F_prev3_success
```

이유:

- F의 시즌별 환경 변화가 큼
- 상대 모집단 자체가 변함
- 오래된 F lag의 의미가 현재와 안정적으로 연결되지 않음
- 추가 분할로 sample size가 더 감소

대신:

```text
current game_type
old-F sample weighting
```

은 유지한다.

선택 ablation:

```text
All-game seasonal profile
vs
R-only seasonal profile
```

---

# 10. old-F Sample Weight

현재 기준 weight는 유지한다.

```text
R             = 1.00
F 2019~2022   = 0.25
F 2023~       = 1.00
```

Temporal representation과 sample weighting을 동시에 바꾸지 않는다.

---

# 11. Era-normalized FLAT

전체 FLAT 좌표계를 시대보정하는 방식은 폐기한다.

```text
Career Flat
Context Effect
Safe Context
HLogit
Drift
```

를 era-normalized space로 재구축하지 않는다.

\[
\boxed{
Era\ Normalized\ FLAT = DROP
}
\]

단, single-season temporal trend에서 league drift를 제거하는 것은 별도 개념이다.

---

초기 temporal experiment는 다음 arm으로 분리한다.

```text

T1_ABS_LEVEL
```

# 13. Prior / Group Feature 검정 규칙

새로운 prior나 group statistic을 추가할 때는 다음 검정을 기본으로 한다.

```text
1. 새 prior의 행가중 평균 확인
2. 기준 prior와 평균이 다른지 확인
3. 필요하면 centered version 비교
4. level-only control을 같이 실행
5. 개인차 성분이 level-only control을 실제로 넘는지 확인
```

이 절차를 통과하지 못한 개선은 feature signal로 인정하지 않는다.

# PART B. Deep Learning Branch — Structured Transformer

# 14. DL Branch의 목적

DL은 CatBoost보다 더 많은 정보를 넣는 모델이 아니다.

V1의 핵심 질문:

> **같은 원천 정보를 다른 구조로 표현하면 CatBoost와 다른 유효한 signal을 만들 수 있는가?**

따라서:

\[
\boxed{
Same\ Information\ Universe
}
\]

를 유지한다.

차이는 feature의 양이 아니라 **representation과 interaction 방식**이다.

---

# 15. CatBoost와 DL의 차이

CatBoost:

```text
prev1
prev2
relative trend
count profile
hand profile
...
→ column-based engineered table
```

Transformer:

```text
[Context × Time] state token
→ token 간 self-attention
```

즉:

```text
CatBoost
→ 사람이 관계를 일부 명시

Transformer
→ token 간 관계를 학습
```

---

# 16. Token 단위

기존의:

\[
Metric\times Context\times Time
\]

구조는 사용하지 않는다.

8 metrics × 6 contexts × 6 times이면 약 288 token이 되어 비효율적이다.

대신:

\[
\boxed{
Token = Context\times Time
}
\]

로 정의한다.

예:

```text
[Overall × Career]
[Overall × Prev1]
[Overall × Prev2]
[Count × Prev1]
[Hand × Current]
...
```

---

# 17. Context 축

초기 V1에서는 CatBoost와 동일 information universe를 사용한다.

대표 Context:

```text
Overall
Hand
Count
Count × Hand
BaseOut
Count × BaseOut
```

---

# 18. Time 축

대표 Time:

```text
Career
Prev3
Prev2
Prev1
Current
Recent
```

따라서 최대:

\[
6\times6=36
\]

정도의 historical state token을 만든다.

실제 token 수는 context별 availability와 구현 범위에 따라 조정 가능하다.

---

# 19. Token 내부 Value Vector

각 `Context × Time` cell 안의 metric은 별도 token으로 쪼개지 않는다.

예:

```text
[Count × Prev1]
```

하나의 token에:

```text
success
middle
reverse
ball
strike

fastball
breaking
offspeed

log1p(n)
availability
```

를 함께 넣는다.

개념적으로:

\[
v_{c,t}
=
[
metrics,\log(1+n),availability
]
\]

---

# 20. Structured Token Encoder

각 cell의 value vector를 작은 MLP로 embedding한다.

\[
h_{c,t}
=
ValueEncoder(v_{c,t})
\]

이후:

\[
Token_{c,t}
=
h_{c,t}
+
E_{context=c}
+
E_{time=t}
\]

형태로 구성한다.

즉 같은 metric이라도:

```text
Count × Prev1
Hand × Prev1
Count × Career
```

는 서로 다른 semantic position을 갖는다.

---

# 21. Availability 처리

Missing은 0과 같은 의미가 아니다.

예:

```text
Prev1 있음
Prev2 없음
Prev3 없음
```

은 짧은 경력 자체를 나타낼 수 있다.

따라서 token 내부에는 반드시:

```text
rate
log1p(n)
availability
```

가 포함된다.

단, availability가:

```text
game_type
season
특정 데이터 수집 체계
```

의 proxy로 작동하는지 EDA로 확인한다.

Missingness shortcut이 확인되면 embedding 설계를 조정한다.

---

# 22. Transformer 구조

초기 모델은 small Transformer로 제한한다.

```text
State Tokens (~36)
       +
Current Context Token(s)
       +
      [CLS]
       │
       ▼
Structured Transformer
       │
       ▼
      [CLS]
       │
       ▼
Prediction Head
       │
       ▼
P(Control Success)
```

초기 범위:

```text
d_model = 64
heads   = 4
layers  = 2~3
FFN     = 128~256
dropout = 0.10~0.20
```

원칙:

\[
\boxed{
Small\ Model
+
Strong\ Structure
}
\]

---

# 23. Transformer에서 Temporal Trend 처리

CatBoost는 explicit trend를 직접 제공할 수 있다.

Transformer에서는 기본적으로:

```text
Prev1 token
Prev2 token
Prev3 token
```

을 따로 제공하고 Attention이 관계를 학습하게 한다.

즉:

```text
CatBoost
→ explicit relative trend

Transformer
→ temporal token interaction
```

을 기본 차이로 둔다.

필요할 경우 trend token은 후속 ablation에서만 추가한다.

---

# 24. DL V1에서 제외하는 정보

초기 Transformer에는 다음을 넣지 않는다.

```text
pitcher_id
TrackMan
CatBoost Latent Skill
과도한 high-order sparse context
F-specific temporal lag
CatBoost-derived auxiliary prediction
```

이유:

> DL V1의 목적은 추가 정보가 아니라 구조 자체의 효과를 검정하는 것이기 때문.

---

# 25. Latent Skill 제외 이유

Latent Skill은 이미 CatBoost 기반으로 생성된 값이다.

이를 DL에 넣으면:

```text
CatBoost-derived signal
→ DL Branch
```

가 되어 두 branch가 커플링된다.

앙상블 diversity 검정에 불리하므로 V1에서는 제외한다.

---

# 26. MLP Sanity Baseline

Transformer 전에 동일한 state matrix를 flatten해서 MLP를 학습한다.

```text
36 state cells
→ flatten / concatenate
→ MLP
→ P(success)
```

목적:

- 입력 block 자체가 유용한지 확인
- Transformer가 MLP보다 interaction을 더 잘 학습하는지 비교
- preprocessing 오류 탐지

단:

> MLP가 실패했다고 Transformer를 자동 폐기하지 않는다.

MLP는 sanity baseline이지 hard gate가 아니다.

---

# 27. Token Dropout

DL에는 Token Dropout을 사용할 수 있다.

예:

```text
[Prev1 × Count]   keep
[Prev2 × Count]   mask
[Career × Hand]   keep
[Prev3 × BaseOut] mask
```

목적:

- 특정 noisy historical cell에 과도하게 의존하는 것 방지
- missing pattern에 대한 robustness 증가
- broader representation 학습

---

# 28. DL 학습 목표

최종 target:

```text
Control Success
```

초기 loss:

```text
BCEWithLogitsLoss
```

old-F sample weight는 CatBoost와 동일하게 적용해 학습 조건을 통제한다.

# 29. DL Early Stopping Protocol

2024를 early stopping에 사용하지 않는다.

## Step 1 — Epoch 선택

```text
Train = 2019~2022
Valid = 2023
```

여기서 best epoch:

\[
E^*
\]

를 선택한다.

2023은 성능 주장용 benchmark가 아니라 **training control용 temporal holdout**이다.

---

## Step 2 — 2024 최종 validation

```text
Train = 2019~2023
Epoch = E*
Valid = 2024
```

2024는 architecture와 ensemble의 최종 판정을 위해 한 번만 사용한다.

---

## Step 3 — 최종 제출

```text
Train = 2019~2024
Epoch = E*
Test  = 2025
```

`E*`에 데이터 증가 비율을 곱하지 않는다.

# PART C. Ensemble

# 30. Ensemble 원칙

초기 blend weight는 미리 고정한다.

기본:

\[
\boxed{
P_{final}
=
0.8P_{CB}
+
0.2P_{DL}
}
\]

초기 실험에서는 이 weight를 최적화하지 않는다.

목적:

> validation에 맞춘 weight tuning이 아니라 DL이 실제 complementary signal을 제공하는지 확인

---

# 31. 성공 기준

Transformer standalone 성능만으로 성공 여부를 판단하지 않는다.

확인 항목:

```text
CatBoost Brier
DL Brier
80/20 Blend Brier
Prediction Correlation
Residual Correlation
R Brier
F Brier
```

최종 판정 우선순위:

\[
\boxed{
Blend\ Brier
>
Standalone\ Brier
>
Correlation
}
\]

Residual correlation은 진단 지표일 뿐이다.

낮은 residual correlation이 반드시 좋은 것은 아니다.

```text
새로운 signal
→ correlation 감소
→ blend 개선
```

일 수도 있지만,

```text
noise 증가
→ correlation 감소
→ blend 악화
```

일 수도 있다.

---

# 32. Blend Weight Sensitivity

80/20에서 실제 개선이 확인된 뒤에만 coarse sensitivity를 본다.

예:

```text
90 / 10
80 / 20
70 / 30
```

`0.73 / 0.27`처럼 validation에 맞춘 정밀 weight 탐색은 하지 않는다.

# PART D. 별도 트랙

# 33. 2025 Logit Shift / Level Calibration

2025의 league base rate가 추가로 내려갈 것이라고 가정해:

\[
logit(p)\rightarrow logit(p)+c
\]

를 적용하는 것은 **모델 구조와 분리한다.**

```text
Model Prediction
      ↓
Optional 2025 Level Calibration
      ↓
Submission
```

이것은:

> feature engineering 또는 model improvement가 아니라 2025 league-level prior에 대한 별도 베팅

이다.

따라서 ML/DL model selection과 섞지 않는다.
